# UniversalFSMPresentation — базовый пример

Независимый персонаж с четырьмя состояниями демонстрирует все девять встроенных типов эффектов и пользовательский эффект оттенка.

## Запуск

1. Установите UniversalFSM 0.2.0 и Presentation 0.3.2.
2. Импортируйте пример через Package Manager.
3. Выберите **Tools > Примеры Presentation > Создать демонстрационную сцену**.
4. Запустите Play Mode и используйте кнопки.

Генератор предлагает сохранить изменённые сцены и открывает новую изолированную сцену, чтобы камеры и AudioListener из других сцен не конфликтовали с примером. Отмена диалога сохраняет текущий набор сцен. В уникальной папке `Assets/PresentationValidation` создаются квадратный спрайт, четыре анимационных клипа, Animator Controller, WAV-звук, префаб и материал частиц, определение FSM, доменный профиль, профиль эффектов и ассеты эффектов. Затем сохраняется `PresentationValidation.unity`. Пакетный запуск пропускает диалоги и предназначен для отдельного проверочного проекта. Сторонние игровые ассеты не используются.

| Кнопка | Что демонстрирует |
|---|---|
| Бег | Плавный переход Animator, однократный звук, частицы с временем жизни состояния |
| Покой | Очистка при выходе и начальная видимость оружия |
| Прыжок | Анимация прыжка и один остаточный силуэт |
| Атака | Переход Animator по триггеру, оружие, импульс камеры, собственный оттенок |
| Урон | Точное доменное событие, вспышка, силуэт и длительность остановки времени из данных события |
| Сбросить | Очистка эффектов перед сбросом FSM |
| Отключить / включить эффекты | Жизненный цикл ручной привязки источника состояний и шины событий |

Кнопки принудительно переключают допустимые состояния FSM, чтобы отдельно показать поведение эффектов. Эти состояния не реализуют перемещение игрока, ИИ или автоматические переходы по завершению анимации. Покой, бег и прыжок используют прямое переключение Animator. Атака устанавливает триггер, который обрабатывается переходом Any State → Attack; эффект выхода из атаки сбрасывает ожидающий триггер. Ключи слоя `Main` и пути Animator `Base Layer.*` остаются техническими идентификаторами.

## Файлы

- `BasicPresentationDomainProfile.cs` — контекст, четыре состояния и сборка доменной конфигурации.
- `BasicPresentationDemo.cs` — кнопки, шина событий персонажа, передача данных и жизненный цикл.
- `BasicCameraImpulse.cs` — пример адаптера камеры.
- `SampleTintCue.cs` — переиспользуемый эффект, хранящий изменяемое состояние на персонаже.
- `Editor/BasicPresentationSceneBuilder.cs` — создание ассетов и сцены в уникальной папке.

Во время настройки драйвер сохраняет ссылку на контроллер, чтобы Validate Setup мог сравнить определения. В Start пример очищает это поле и сам управляет привязкой, включая свою шину событий. Так автоматическое повторное включение не выполняет вторую привязку следом за ручной.

Пример восстанавливает привязку после повторного включения персонажа или компонента управления. Его кнопка немедленно восстанавливает или скрывает постоянные визуальные изменения. Проверка изменения активности также обнаруживает прямое включение или отключение драйвера из инспектора либо другого скрипта к моменту LateUpdate: при включении выполняется одна привязка, при отключении — очистка визуальных изменений примера. В обычных кадрах повторной привязки нет. Сброс и отключение скрывают оружие, очищают ожидающий триггер Attack и отменяют смещение камеры через `BasicCameraImpulse.CancelImpulse()`. Это правила примера: сам пакет не отменяет произвольное переключение объектов и не управляет системой камеры.

## Отрисовка и ожидаемое поведение

Генератор выбирает шейдер частиц для встроенного конвейера или URP; запасной вариант — шейдер спрайта. Для других конвейеров может потребоваться совместимый материал. Пример не зависит от пакета URP.

Частицы бега останавливаются при выходе из этого состояния. Эффекты выхода скрывают оружие при обычном переходе; вспомогательная очистка также скрывает его при сбросе и отключении. Событие урона передаёт длительность 0,12 секунды и использует общий координатор остановки времени. Вместимость пулов фиксирована и видна в сцене. Завершение и отмена импульса камеры находятся под управлением адаптера примера.
