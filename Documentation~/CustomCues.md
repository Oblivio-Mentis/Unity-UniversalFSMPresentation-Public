# Собственные эффекты и адаптеры камеры

Унаследуйте `PresentationCue`, чтобы добавить эффект, которого нет в пакете. Храните неизменяемые настройки в отдельном ассете, а изменяемое состояние каждого персонажа — в компонентах сцены.

## Полный пример эффекта

В примере есть [SampleTintCue.cs](../Samples~/BasicPresentation/SampleTintCue.cs). Он передаёт управление временем жизни и восстановлением существующему компоненту вспышки персонажа:

```csharp
using OblivioMentis.Presentation;
using OblivioMentis.UniversalFSM;
using UnityEngine;

[CreateAssetMenu(menuName = "FSM/Presentation/Свои эффекты/Оттенок спрайта")]
public sealed class TintCue : PresentationCue
{
    public Color color = Color.yellow;
    [Min(0.001f)] public float duration = 0.15f;

    public override void Execute(FsmPresentationDriver driver,
                                 in UniversalFsmSignal signal)
    {
        if (driver.spriteFlash != null)
            driver.spriteFlash.Flash(color, duration);
    }

    public override void Stop(FsmPresentationDriver driver)
    {
        if (driver.spriteFlash != null)
            driver.spriteFlash.Clear();
    }
}
```

Сохраните код в `TintCue.cs` в сборке исполнения, ссылающейся на обе сборки Runtime пакетов. Создайте ассет через его собственное меню и перетащите в список эффектов профиля. Пользовательские типы не добавляются автоматически в фиксированное меню **+ Add Effect**.

Пример использует общий компонент вспышки драйвера, поэтому его Stop очищает вспышку этого персонажа. Если эффекту нужно отдельное владение, добавьте специализированный компонент с API получения и освобождения ресурса по ключу. Не храните текущий Renderer, владельца, корутину или таймер в общем ассете.

## Контракт Execute

Execute исполняется синхронно в главном потоке Unity. Он получает драйвер и полный `UniversalFsmSignal`. Сигналы состояний содержат слой и числовые идентификаторы; строки имён могут быть пустыми. Доменные сигналы передают точный ключ, `IntPayload` и `UniversalFsmDomainPayload`.

Структура данных содержит основные и дополнительные строковые ID, идентификатор события, ID источника и цели, флаги, значение, длительность, двумерную позицию и направление. Их смысл определяет игровой код. Нельзя предполагать, что у каждого события заполнена длительность или что сигнал состояния содержит боевые данные.

Данные, нужные после вызова, копируйте в компонент персонажа. На этой границе проверяйте конечность чисел и диапазоны. Не меняйте списки действий профиля во время рассылки; настройку и повторную привязку выполняйте вне неё.

## Контракт Stop

Драйвер запоминает уникальные выполненные ассеты. Сброс, отвязка и отключение вызывают Stop один раз на ассет, даже если тот выполнялся многократно. Поэтому Stop должен освободить все ресурсы этой пары «эффект — драйвер» и быть безопасным после естественного завершения.

- Сделайте Stop идемпотентным.
- Очистка не должна зависеть от того, виден ли сейчас эффект.
- Управляйте созданными подписками и отменяйте их.
- Не выполняйте повторную привязку драйвера во время очистки.
- Не восстанавливайте глобальное состояние, которым уже управляет другая система.

Исключения пользовательских Execute и Stop записываются и изолируются. Ошибка остаётся наблюдаемой, а остальные эффекты могут продолжить работу. Это не отменяет необходимости проверять настройки.

## Адаптер камеры

Реализуйте `IUniversalFsmCameraImpulseSink` на MonoBehaviour и назначьте компонент в поле Camera Sink драйвера. Полный [BasicCameraImpulse.cs](../Samples~/BasicPresentation/BasicCameraImpulse.cs) запоминает локальную позицию камеры, добавляет короткое боковое колебание по немасштабированному времени и восстанавливает позицию при завершении или отключении. Публичный `CancelImpulse()` позволяет владельцу сброса или отключения немедленно вернуть позицию, не меняя интерфейс пакета.

Игровая система камеры должна объединять импульс с сопровождением и прицеливанием, а не давать нескольким скриптам независимо записывать конечный Transform. Единицы амплитуды определяет адаптер. Пакет только передаёт амплитуду и длительность и изолирует исключения обработчика.

## События анимации и точный момент эффекта

Для шагов, следа оружия или эффекта в конкретном кадре добавьте обработчик на анимируемый объект. AnimationEvent вызывает этот компонент, а он публикует доменное событие или обращается к выделенному компоненту эффекта. Явно разделяйте полномочия: событие анимации сообщает о кадре, а Combat проверяет попадания и урон.

Встроенного планировщика задержек, циклических последовательностей и составных частиц нет. Реализуйте нужное поведение в игровом компоненте с явной отменой и запускайте его пользовательским эффектом.
